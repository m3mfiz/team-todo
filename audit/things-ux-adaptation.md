# Things 3 (iOS) → team-todo: исследование UI/UX и варианты адаптации

> Исследование от 2026-07-04. Дополняет `things-design-audit.md` (обязательная дизайн-спека): раздел 1 — факт текущей реализации, раздел 2 — внешние источники, разделы 3–4 — предложения.

## 1. Текущее состояние клиента team-todo

### 1.1 Что из Things-языка уже реализовано

**Визуальная система.** Белый фон без карточных теней (задачи — строки с hairline-разделителями), акцентный синий `--blue: #3b82f6`, true-black тёмная тема через `prefers-color-scheme: dark` с полной переиндексацией CSS-переменных (`styles.css:50–70`). Системный шрифт SF Pro; заголовок раздела 32px/800/−0.03em, строка задачи 16px, мета 13px `--gray` — всё в диапазонах спеки `things-design-audit.md`.

**Чекбокс и завершение.** Круг 28px с тонкой обводкой, при отметке заливка синим за 200ms + галочка scale(0→1); выполненная задача остаётся в списке ~1.4s (`COMPLETE_LINGER_MS = 1400`, `App.tsx`) и уходит с fade — практически идентично Things (у них ~1.5s).

**Структура.** Четыре раздела с Things-цветными иконками: Сегодня (жёлтая звезда), Предстоящие (красный календарь, группировка по датам с заголовками «5 июня, Среда», дальше по месяцам), Все задачи (бирюзовые слои), Журнал (зелёная галочка, группировка по дате завершения). Таб-бар с бейджами, FAB 56px как аналог Magic Plus.

**Взаимодействие.** Раскрытие задачи inline (не отдельный экран): view-first карточка с серым фоном, редактирование per-field по тапу, Сохранить/Отмена появляются только при изменениях. Добавление — bottom sheet с grabber и анимацией снизу. Тач-цели ≥44px, инпуты ≥16px (iOS zoom), safe-area insets.

### 1.2 Пробелы относительно спеки и Things

- **Нет поиска (Quick Find)** — единственный крупный отсутствующий паттерн Things; спека его не требовала, но в Things это ключевой инструмент навигации.
- **Upcoming — линейный список**, без календарной сетки/мини-календаря Things.
- **Нет свайпов на строках** (отметить/перенести дату) — осознанное решение спеки («свайпы заменяем явными контролами»), но у Things свайпы — половина скорости работы.
- Просрочка решена информативнее Things (chip «Просрочено · дата» вместо лаконичной красной пометки) — отклонение, а не пробел.

### 1.3 Командная специфика, которой нет в Things (ограничения адаптации)

- **«Кому» / исполнитель**: chip «Всем» в строке, факт «Кому» в карточке, select для админа; сегмент-фильтр по исполнителям в шапке (только админ).
- **Общие задачи с per-member completion**: блок «ВЫПОЛНЕНИЕ» в карточке — точки 18px (пустая/зелёная с галочкой) + имя + дата; оптимистичная отметка, глобальный `done` только когда отметили все.
- **Роли**: дедлайн и исполнитель меняет только админ; в мете строки «от {автор}» / «для {исполнитель}»; журнал у админа — сводный.
- **UsersScreen** (по тапу на имя в шапке, только админ): список сотрудников, смена паролей, добавление/удаление — экран, у которого в Things вообще нет аналога.
- **Login-экран** — также вне языка Things, стилизован под общий вид.

## 2. Исследование Things 3 для iOS

### 2.1 Визуальная система

**Типографика.** Things использует системный шрифт ОС и уважает Dynamic Type (обновление 3.18 «Things Big and Small», 2023); все иконки переведены в вектор, чтобы масштабироваться вместе с текстом. Точные кегли Cultured Code не публикует. Иерархия строится без разделителей и рамок: строки читаются как «просто текст», пока задача не «поднимется из фона карточкой».

**Цвет.** Цвет функционален, не декоративен: красные даты — дедлайны/просрочка, жёлтая звезда — метка Today вне самого списка Today, цвета областей/проектов — для сканирования нагрузки. Тёмный режим с Things 3.8 (2018) — три варианта: Light, Dark и **Black** (true-black для OLED, «граница между устройством и приложением исчезает»). Официальных hex-значений нет — палитра нашей спеки `things-design-audit.md` — собственная аппроксимация проекта, что нормально.

**Экраны.** Шесть канонических списков: Inbox, Today (+ подсекция **This Evening** внизу — «задачи на вечер видны, но не мешают»), Upcoming (ближайшие 7 дней по дням, дальше по месяцам; в ленту вшиты события календаря), Anytime (активные незапланированные), Someday (идеи без даты, скрыты из рабочих видов), Logbook (вечный архив достижений) + Trash. Проекты показывают **Progress Pie** — круговой индикатор заполнения по мере выполнения задач; заголовки (headings) делят проект на секции и перетаскиваются целиком.

**Анатомия строки.** Круглый чекбокс, заголовок, лёгкая строка меты; никаких карточек и линий — разделение пробелами. Отметка выполнения даёт хаптик; снятие отметки с выполненной задачи требует подтверждения (защита от промаха). Поведение выполненных настраивается: исчезать в журнал сразу или оставаться в списке (наш фиксированный linger 1.4s — собственная интерпретация, Things таймера не имеет).

**Белая карточка.** Тап по строке «плавно превращает её в чистый лист бумаги»: строка морфится в карточку, остальной список отступает в фон. На карточке: заголовок, заметки (в них же живёт чек-лист), теги, «Когда» (дата начала) и отдельный «Срок» (deadline) — вторичные поля «спрятаны в углу, пока не понадобятся». Важно: **When ≠ Deadline** — запланированность и крайний срок в Things — разные оси.

**Quick Find.** На iPhone — потянуть список вниз (позже — тап по заголовку списка). Сначала мгновенный поиск по именам задач/проектов/тегов, «Continue Search» расширяет на заметки, чек-листы и журнал. Работает и как навигация: набрал имя списка — перешёл. Через Quick Find доступны скрытые списки: Tomorrow, Deadlines, Repeating, All Projects, Logged Projects.

**Пустые состояния.** Точные строки микрокопии Things в открытых источниках не публикуются (проверено) — тон известен: спокойный, поощряющий, без восклицаний.

### 2.2 Взаимодействия и анимации

**Magic Plus.** Кнопку «+» можно не только нажать, но и перетащить: в конкретное место списка (задача создаётся там), на левый край (заголовок-heading), на цель Inbox в углу (задача в Inbox из любого списка). Перетаскивание сопровождается хаптиком.

**Свайпы и выделение.** Свайп **вправо** по строке открывает планировщик «Когда»; свайп **влево** — выделение с входом в multi-select (кружки выделения по правому краю, протяжка по ним выделяет диапазон; внизу — тулбар Move/…). Long-press «выдёргивает» задачу из списка для переноса (drag-reorder), группой — тоже.

**Завершение и раскрытие.** Хореографию анимаций (заливка чекбокса, морф строки в карточку) и тайминги Cultured Code не публикуют — «собственный анимационный тулкит»; поведение и защита от промаха описаны в 2.1.

**Планировщик «Когда».** Быстрые пресеты: Today, This Evening, Someday + календарь; pull-down в пикере — ввод даты естественным языком. Задача с дедлайном, но без When, остаётся в Anytime (см. When ≠ Deadline в 2.1).

**Бейдж и уведомления.** Бейдж иконки настраивается, работает только пока приложение «живо» (как Apple Mail); напоминания — разовые нотификации.

#### Матрица осуществимости в PWA (iOS standalone)

| Взаимодействие | Осуществимость | Примечание |
|---|---|---|
| Свайп по строке (действия) | ✅ дёшево | touch events + transform; `overscroll-behavior: contain` |
| Пресеты «Когда» (bottom-sheet) | ✅ дёшево | обычный компонент |
| Анимация чекбокса + linger | ✅ есть | уже реализовано |
| Pull-down поиск | ✅ дёшево | приручить rubber-band скролл |
| Бейдж иконки | ✅ с оговоркой | `setAppBadge()` — iOS 16.4+, только установленная PWA, нужно разрешение на уведомления; вызывается из SW в push-обработчике |
| Морф строка→карточка | ⚠️ дорого точно / дёшево упрощённо | View Transitions — только Safari 18+; надёжный путь — FLIP (framer-motion `layoutId`) или CSS-приближение |
| Multi-select + drag-reorder | ⚠️ дорого | нативный HTML5 DnD **не срабатывает от пальца** на iOS — только Pointer Events вручную или dnd-kit |
| Magic Plus drag-to-position | ⚠️ дорого | ручной hit-testing + автоскролл |
| Хаптик | ❌ невозможно | Vibration API отсутствует в iOS WebKit; компенсировать анимацией/звуком |
| Звук отметки | ✅ с оговоркой | требуется user-gesture unlock аудио |

Непроверенные элементы (источники не подтвердили — не считать фактами): «jar»-анимация пикера, шорткат «Weekend», выделение двухпальцевым свайпом.

## 3. Варианты адаптации

Клиент уже «говорит» на языке Things (раздел 1), поэтому варианты — не редизайн, а три глубины доводки. Каждый следующий включает предыдущий.

### Вариант A — «Полировка» (лёгкий, ~1–2 дня)

Дополняет недостающие Things-паттерны без изменений модели данных и зависимостей.

| # | Что | Как | Файлы | Оценка |
|---|---|---|---|---|
| A1 | **Поиск (Quick Find)** | Кнопка-лупа в шапке + жест «потянуть список вниз»; мгновенный клиентский фильтр по названию (все видимые задачи уже на клиенте), переключатель «искать и в заметках». Результаты — обычные TaskRow с подсветкой совпадения. | `App.tsx` (state+инпут), `TaskList.tsx`, `styles.css` | 0.5–1 д |
| A2 | **Progress Pie для общих задач** | Вместо текстового chip «Всем» — мини-«пирог» в стиле проектов Things: SVG-кружок, заполненный сектором `отметило/всего` (данные уже в `completions[]`), рядом «2 из 4». Командная фича начинает выглядеть по-Things'овски. | `icons.tsx` (PieIcon), `TaskRow.tsx`, `styles.css` | 0.5 д |
| A3 | **Подтверждение снятия отметки** | В журнале первый тап по чекбоксу показывает «Вернуть?» (паттерн уже есть у удаления), второй — возвращает. Прямое заимствование защиты от промаха Things. | `TaskRow.tsx` | 0.5 ч |
| A4 | **Пустое состояние с иконкой** | Крупная приглушённая иконка раздела над текстом пустого состояния (как «спокойные» пустые экраны Things). | `TaskList.tsx`, `styles.css` | 0.5 ч |

Риски: минимальные. Жест pull-down должен не конфликтовать с резиновым скроллом (`overscroll-behavior: contain`); при сомнении — оставить только кнопку-лупу.

### Вариант B — «Взаимодействия» (средний, ~3–5 дней, включает A)

Возвращает «скорость руки» Things — свайпы, пресеты дат, морф карточки, бейдж.

| # | Что | Как | Файлы | Оценка |
|---|---|---|---|---|
| B1 | **Шит «Срок» с пресетами** | Вместо голого `input[type=date]` — bottom-sheet в духе пикера «Когда»: Сегодня / Завтра / Через неделю / Убрать срок / календарь. Используется в карточке и AddSheet (права не меняются: срок — админ, при создании — любой). | новый `WhenSheet.tsx`, `TaskRow.tsx`, `AddSheet.tsx`, `styles.css` | 1 д |
| B2 | **Свайп по строке (role-aware)** | Одно быстрое действие свайпом вправо, по роли: член — отметить/снять свою отметку; админ — открыть шит «Срок» (аналог свайпа-«Когда» в Things). Порог+`translateX`, отмена по вертикальному скроллу. Свайп влево не вводим (multi-select не делаем). | `TaskRow.tsx`, `styles.css` | 1–1.5 д |
| B3 | **Морф строка→карточка (упрощённый)** | CSS-приближение «белой карточки»: при раскрытии фон списка слегка затемняется/отступает (backdrop), карточка приподнимается (shadow+scale 250–300ms), обратная анимация при закрытии. Без framer-motion и View Transitions (Safari 18+ нельзя требовать). | `TaskRow.tsx`, `App.tsx` (backdrop), `styles.css` | 0.5–1 д |
| B4 | **Бейдж иконки** | `navigator.setAppBadge(число задач «Сегодня»)`: точный пересчёт при открытии/поллинге, инкремент из SW при пуше. iOS 16.4+, только установленная PWA, после разрешения на уведомления — деградирует бесшумно. | `sw.ts`, `push.ts`, `App.tsx` | 0.5 д |

Риски: свайп против скролла — самый тонкий пункт (нужны честные пороги и отмена); морф не должен ломать существующий view-first паттерн; бейдж — только для установивших PWA (сегментация уже принята для пушей).

### Вариант C — «Глубокая адаптация» (1–2+ недели, включает B)

Переносит семантику Things, а не только вид. Дорого и спорно для команды из нескольких человек.

| # | Что | Суть | Цена |
|---|---|---|---|
| C1 | **«Когда» ≠ «Срок»** | Личное поле планирования «Когда» (любой ставит себе), отдельное от дедлайна: «Сегодня» наполняется тем, что ты решил делать сегодня, а не только горящими сроками. Миграция БД, права, новая группировка, тесты сервера и клиента. | 3–5 д |
| C2 | **Multi-select + batch (админ)** | Свайп-выделение с кружками, тулбар «Срок/Кому/Удалить» для группы. Ручная state-machine жестов или dnd-kit. | 2–3 д |
| C3 | **Ручной порядок (drag-reorder)** | Long-press перенос строк; нужен `sort_order` в БД, API и разруливание с группировкой по датам. Нативный HTML5 DnD на iOS от пальца не работает — только dnd-kit/Pointer Events. | 2–3 д |
| C4 | **Секция «Вечером»** | Подсекция в «Сегодня» (this-evening флаг). Осмысленна только вместе с C1. | 1 д |

Риски: C1 меняет ментальную модель (двое суток объяснять команде «чем Когда отличается от Срока»); C3 конфликтует с автогруппировкой по датам (в Things порядок живёт внутри проектов, у нас проектов нет); суммарная ценность для 2–5 пользователей не очевидна.

## 4. Рекомендация

**Делать: A целиком + B1 и B3; затем по обратной связи — B2 и B4. C — не делать сейчас.**

Обоснование:
- A закрывает единственный крупный пробел (поиск) и переводит главную командную фичу (общие задачи) на родной язык Things (Progress Pie) — максимум эффекта за день-два.
- B1 (пресеты срока) и B3 (морф карточки) — самые ощутимые «Things-моменты» из среднего пакета при низком риске.
- B2 (свайпы) стоит делать после — это самый рискованный по жестам пункт; B4 (бейдж) — приятный бонус для установивших PWA.
- Из C единственный кандидат на будущее — C1 (When≠Deadline), и только если команда начнёт планировать день, а не только вести дедлайны. C2/C3 при текущем размере команды не окупаются.
